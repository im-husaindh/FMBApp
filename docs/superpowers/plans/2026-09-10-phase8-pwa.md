# FMBRequestThali — Phase 8: PWA Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The app is installable to a home screen on Android, iOS, and desktop browsers (manifest + generated icons), and shows a plain, honest banner when the device goes offline.

**Architecture:** Next.js 16's built-in, non-experimental file conventions — `app/manifest.ts` and code-generated `icon.tsx`/`apple-icon.tsx` routes via `next/og`'s `ImageResponse` — provide installability with zero new dependencies and no external design asset. A small client component using the browser's native `online`/`offline` events, mounted once in the root layout, provides the "offline-friendly messaging" the spec asks for.

**Tech Stack:** Next.js App Router file conventions (`manifest.ts`, `icon.tsx`, `apple-icon.tsx`), `next/og`'s `ImageResponse`, React client component with `useEffect`.

**Spec:** `docs/superpowers/specs/2026-09-10-phase8-pwa-design.md`

## Global Constraints

- No new test-framework dependency gets introduced for this phase. This repo has zero `.test.tsx` files and no `@testing-library/react`/jsdom/happy-dom — the spec deliberately has no automated component test for the offline banner; live/manual browser verification (Task 4) is this phase's actual correctness check. Do not add a component-testing setup.
- The three generated icons' font-size-to-canvas-size ratio must stay consistent: 192px canvas → 88px font (0.458), 512px canvas → 232px font (0.453), 180px canvas → 82px font (0.456) — these exact numbers, not approximations.
- `src/app/favicon.ico` deletion happens in the same task that adds `icon.tsx` (Task 2) — the app must never be left in an intermediate state with both the old favicon and the new `icon.tsx` present, which is a conflicting file-convention state for the same `<link rel="icon">` slot.
- This phase touches no database, no Server Action, no RLS, no migration. If any task's implementer finds themselves about to touch any of those, that's a signal the task has drifted out of scope — stop and reconsider rather than proceeding.
- No install-prompt UI (a custom "Add to Home Screen" button) is in scope — out of scope per the spec, modern browsers surface their own native install prompt once the manifest criteria are met.

### Task 3: Offline banner + root layout wiring

**Files:**
- Create: `src/components/offline-banner.tsx`
- Modify: `src/app/layout.tsx`

**Interfaces:**
- Consumes: nothing from Tasks 1-2.
- Produces: `OfflineBanner` (a default-exportless named export, React client component, no props), mounted in the root layout so every route in this app renders it.

`src/components/` already exists in this repo (`src/components/ui/`, `src/components/menu/`, `src/components/thali/`, `src/components/concerns/`) — `offline-banner.tsx` goes directly in `src/components/`, not a new subdirectory, since it's a layout-level component with no domain to group it under.

- [ ] **Step 1: Write the offline banner component**

```tsx
// src/components/offline-banner.tsx
'use client';

import { useEffect, useState } from 'react';

export function OfflineBanner() {
  const [isOffline, setIsOffline] = useState(false);

  useEffect(() => {
    setIsOffline(!navigator.onLine);
    const handleOnline = () => setIsOffline(false);
    const handleOffline = () => setIsOffline(true);
    window.addEventListener('online', handleOnline);
    window.addEventListener('offline', handleOffline);
    return () => {
      window.removeEventListener('online', handleOnline);
      window.removeEventListener('offline', handleOffline);
    };
  }, []);

  if (!isOffline) return null;

  return (
    <div role="status" className="bg-amber-50 px-4 py-2 text-center text-sm text-amber-800">
      You&apos;re offline. Some actions won&apos;t work until your connection returns.
    </div>
  );
}
```
